【プロジェクト背景】

既存の Battle Spirits ゲームエンジンは、複雑な機能（継召、フラッシュ、複数シンボル、スキル等）を詰め込みすぎていて、「修正したところがまた壊れる」という問題が頻発していました。

原因分析:
  - ファイル間の依存関係が不明確
  - データフロー（UI → Server → Engine）の各層で何をすべきかが曖昧
  - 「治ったところがまた壊れる」は、実は設計が悪い証拠

結論: 実装を直す前に、まず設計を完全に決める必要がある


【プロジェクトの理念】

「ルール優先設計」アプローチ：
  1. ゲームルールを完全に定義する（日本語の仕様書レベル）
  2. ルールから必要なデータ構造を導き出す（型定義）
  3. データ構造から依存関係を分析する（層の責務分離）
  4. 初めて実装を始める（コード化）

このアプローチにより：
  - 「何が必要か」が明確になる
  - 層ごとの責務が明確になる
  - 修正時に「どこを直すと何が壊れるか」が予測可能になる

【ゲン＝ガタとは】

最小限のカード。効果は一切ない。

ルール仕様:
  - 初期生命: 5（両プレイヤー）
  - 初期手札: 4枚（全部ゲン＝ガタ）
  - コスト: 4（召喚に必要なコア数）
  - BP（攻撃力）: 5000
  - ダメージ: 1（毎回相手に与えるダメージ）
  - 効果: なし

このゲームだけでも「ターン進行」「リソース管理」「勝利条件」の全てが含まれる。
複雑な効果なしで、完全に動作する。

【重要な設計決定】

1. シンボルの種類を分離

   軽減シンボル（reduction）:
     - コスト支払い時に軽減に使える
     - 例: 「赤シンボル3個まで軽減可能」

   通常シンボル（symbol）:
     - カードが持つシンボルマーク
     - 別の機能（継召等）で使われる

   → 層2のルール定義で両方が必要

2. フラッシュタイミングの層

   フラッシュ = 割り込みでカード効果を発動すること
   フラッシュタイミング = 割り込みが可能な瞬間

   配置: 層2（基本ルール）
   理由: 全デッキで必須の基本的な割り込みルール

   vs. 継召（軽減シンボル使用）
   配置: 層2（コスト支払いルール）
   理由: カード召喚・配置時の全般的なコスト支払い方法

3. ダメージ値の定義場所（未決定）

   候補A: CardLevel単位で定義
     { level: 1, bp: 5000, damage: 1 }
     → レベルによってダメージが異なるカードに対応可能

   候補B: Card単位で定義
     { damage: 1, levels: [...] }
     → シンプルだが、レベル別ダメージに未対応

   判断基準: 将来のカード設計で「レベル別ダメージ」が出てくるか？

【軽減シンボルのルール（層2）】

定義:
  「カード召喚時、軽減シンボル数まで、フィールドの対応するシンボルがあればコストを軽減する」

重要な制約:
  「フィールドに軽減対応シンボルがあるのに、コストを過剰に支払うことはできない」

計算方法:
  軽減額 = min(カードの軽減シンボル数上限, フィールドの対応するシンボル数)
  実際に支払うコスト = max(0, カードのコスト - 軽減額)

例（仮想）:
  ゲン＝ガタ: コスト4、軽減3（赤）

  シナリオ1) フィールドに赤シンボル2個の場合
    軽減額 = min(3, 2) = 2
    実コスト = 4 - 2 = 2コア

  シナリオ2) フィールドに赤シンボル5個の場合
    軽減額 = min(3, 5) = 3
    実コスト = 4 - 3 = 1コア

  シナリオ3) フィールドに赤シンボル0個の場合
    軽減額 = min(3, 0) = 0
    実コスト = 4 - 0 = 4コア


【PlayerState の構造】

type PlayerState = {
  // 基本情報
  life: number;

  // ゾーン
  hand: Card[];           // 手札
  deck: Card[];           // デッキ
  reserves: number;       // リザーブ（コア数）
  trashCores: number;     // トラッシュ内のコア数
  field: Spirit[];        // 場（スピリット・ネクサス）
  trash: Card[];          // トラッシュ（破壊されたカード）
  excluded: Card[];       // 除外ゾーン（継召で使われたカード）
};

ゾーン解説:
  - hand: 最初4枚
  - deck: ゲーム中ドロー
  - reserves: 毎ターン +1、召喚時に -cost
  - trashCores: リフレッシュ時に reserves に戻る
  - field: スピリットを配置したゾーン
  - trash: 破壊されたカードが入る（継召で選べる）
  - excluded: 継召で使われたカード（ゲーム中復帰不可）


【ターンの流れ（簡略）】

1. ドロー: 手札から1枚引く
2. コア獲得: 毎ターン +1 コア（自動）
3. 召喚フェーズ: ゲン＝ガタを召喚可能（コスト4消費）
4. 攻撃フェーズ: 場のゲン＝ガタで攻撃可能（ダメージ1）
5. 攻撃結果: 相手がダメージ受ける → 相手がコア獲得

重要: 攻撃を受けたプレイヤーがコアを獲得する（逆転のチャンス）
